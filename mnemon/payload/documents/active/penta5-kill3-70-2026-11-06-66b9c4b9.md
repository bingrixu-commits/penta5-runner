# penta5 kill3 面板命中率「断崖」诊断：70% 高点是累计曲线随机涨点（2026-11-06）

## 结论（TL;DR）
- 用户问「前天命中率高达 70%，后面一下子断崖下跌」。只读复算 1,202 期 kill3 结算记录后：**70% 不是真实优势，是「今日 / 本版」累计均值在样本少时的随机高点**；11-05 全天实际 59.38%，与其自身随机基线 58.60% 只差 +0.77pp（p=0.79），即就是基线水平。
- 之后的「断崖」由三层叠加：① 展示口径清零（05:00 换日、升 rule_version 会清零累计行）；② 随机均值回归（70% 高点后回落属常态）；③ 缺期（AI 余额守卫在余额 <¥5 时自动关总闸，停预测 → 样本残缺、面板数字乱）。
- 唯一需要盯的结构性候选：kill3 v16（2026-11-06 00:05 上线）n=181 时 50.28% vs 精确基线 58.52%（Δ=−8.25pp，p=0.0243），但**未触发其自身预登记门禁**（z<−2.5 未达，门禁口径 n=180 时 z=−2.351、命中率恰 50.00% 未跌破）；且样本不足（需 276 期才有 80% 把握判 −8pp）。
- 当前 v16 门禁处于**临界**：n≥150 已满足，下一期若不中就使命中率 <50% 从而触发「回滚报告」（脚本只报警，回滚需手动）。
- 不要再把「今日 / 本版」两行当强弱判据；判断版本优劣须看 ≥200 期窗口 + 预登记判据。

## 口径与数据源（审计前提）
- 系统：5 位数字彩票（万千百十个），288 期/天、5 分钟一期；模型只用前 4 球；面板「今日行」按业务日 05:00 清零、「本版行」按 rule_version 清零，二者都是**累计命中率**（不是滚动窗口）。
- 数据：`/root/penta5-runner/data/kill3_tail/settlements.json`（1,202 条已结算，20261030133–20261106196）、`seals.json`（同 1,202 期已发布）；门禁 `data/kill3_v16_guard.json`；总闸 `data/ai_api_control.json`；余额守卫 `data/ai_balance_guard.log`；预案 `ops/kill3-stability-plan.md` §9、回滚 `scripts/kill3_v16_rollback.py --execute`。
- kill3 现行口径 v16 = 8 项合取：2 个计数位置各杀 1 码 + 1 合尾 + 单双反向形态 + 大小反向形态 + 三数共现 3 组；命中 = 8 项全部成立（`group_hit`）。
- 方法：按每条封存自身参数在 10^4 全空间**精确枚举**其整组随机基线 p0（不假设各项独立，保留项间相关），再对 rate−p0 做二项 z 检验与 Wilson 95%CI；随机回撤用 20,000 次 MC（p0=0.5863、burn-in 25 期）。

## 「70%」的真相：累计曲线 + 随机高点
- 11-05：今日行在 n=95（约中午 12:55）摸到 **70.53%**，收盘 288 期回落至 **59.38%**（171 中；自身基线 58.60%，Δ+0.77pp，p=0.7895）。本版 v15 同期峰值 71.13%（n=97），收 62.77%（n=231，基线 58.63%，Δ+4.14pp，p=0.2017）。
- 历史上每天都是同一形态（业务日峰值@样本 → 收盘）：11-01 71.74%@46 → 63.85%（n=260）；11-03 70.27%@37 → 64.71%（n=85）；11-04 76.92%@26 → 61.76%（n=68）；11-05 70.53%@95 → 59.38%（n=288）；11-06 52.58%@97 → 51.64%（n=122，基线 58.53%，Δ−6.89pp，p=0.1224）。
- MC（基线 58.6%、288 期、burn-in 25）：一天内累计曲线某点 ≥70.53% 的概率 **19.8%**（约五天一次）；自最高点回落到收盘 ≥11.15pp 的概率 **20.7%**（中位回落 5.87pp，p90 14.58pp）。11-05 的 70.5→59.4 正落在这类普通回撤内。
- 11-04 的 76.92% 只有 26 期样本、且是深夜恢复后的数据，无统计意义；11-04 白天系统因余额低关闸未出数。

## 「断崖」三层归因
1. **展示口径清零**：05:00 换日、升版清零 → 累计行从 0 重开，n 小时剧烈跳动（11-06 前 20 期仅 25%）。
2. **随机均值回归**：70% 高点本就站不住，回落是数学必然（见上节 MC）。
3. **缺期（运维层）**：`ai_balance_guard` 在余额 <¥5 时自动 pause 总闸。实测：11-04 01:29 关 → 23:03 恢复（21.6 小时，缺 259 期，当日仅 68/288）；11-02 16:43 关 → 11-03 00:33 恢复（7.8 小时，缺 94 期）；11-06 短关 5 次（04:23、07:11、08:00–08:14、11:31–11:34、14:26–14:39），当日缺 15 期（123/138≈89%）。11-05 是最近唯一完整日 288/288——恰是全天 59.38%≈基线的一天。余额守卫日志：14:26 以余额 4.59 触发 pause，14:39 充值到 24.37 后 resume；16:22 last_balance=**¥7.83**，随时会再关闸。
4. 叠加因素：6 天换 14 个版本（v5–v16），30 个 tail 版本中 27 个 n<200（中位 42.5 期）→ 永远小样本，无法判断「稳不稳」。

## v16 是否真的偏低（精确基线核对）
- v16 自 20261106001 起：n=181、hits=91、rate=**50.28%**、精确基线 **58.52%**、Δ=−8.25pp、Wilson 95%CI [43.06%, 57.48%]、z=−2.25、p=0.0243。
- 门禁文件口径（`data/kill3_v16_guard.json`，2026-11-06 16:20 更新）：n=180、hits=90、rate=0.50、expected=0.5863、z=−2.351、thresholds {n_trigger:150, z_trigger:−2.5, rate_floor:0.5}、status=passed（「已达预登记样本 n=180，未触发回滚条件」）。
- 判据：n≥150 且（z<−2.5 或 rate<50%）才触发。当前命中率恰为 50.00%，**下一期若不中即 49.7%<50% 触发**；触发只写报告/告警，回滚需手动执行 `python3 scripts/kill3_v16_rollback.py --execute`（预案 §9）。
- 检测力：检测 p0=0.5863→p1=0.5028（−8.35pp）在 80% power 约需 **276 期**；现 181 期，故「名义偏低、未证实」。
- 项级对照：v16 八项实际率 = 90.00% / 90.00% / 93.75% / 93.75% / 97.96%×3，与各自基线完全一致；整组缺口来自「8 项同时成立」的联合相关性/组合波动（反向形态由被杀位置取反，项间相关，整组方差天然比单项大），不是单项变差。
- 版本对照：v15 231 期 62.77%（+4.14pp）；v12 178 期 64.04%；v13 65 期 56.92%；v14 14 期 64.29%。除 v16 外均与基线不可区分。数据注意：2026-11-06 16:20 复核，重算 group_hit 与账本有 15/1202 不一致（旧版本口径差异，以账本为准）。

## 运维与决策边界
- 模型：`.env` 中 `PENTA5_MODEL_KILL3=deepseek-v4-pro`（2026-11-06 07:20 手动切换；`data/model_tier_guard.json` enabled=false、targets 仅 KILL3，自动回写关闭），每次调用约 1.2 万 token（prompt≈5.3k + completion≈6k），在余额 ¥7.83 下会显著加速关闸；先前审计显示 pro 与 flash 命中率无差异（framework 55.73% vs 55.77%）。
- 真钱边界：仓库存在 `lib/four_throw_robot.py` + `four_throw_urls.json`（active=1、amount=1.2，手动执行会真下注）；用户为手动平台下注（无自动投注服务），并自述「都是照手倍投」。已明确不代下注、不给下注指令、不写下注代码；倍投为负期望放大器（1000 期 EV −¥160,000；1 万本金破产概率 99.79%）。替代方案：纸面影子账本（只动 data/ 与面板只读区块）。
- 面板读数规则（给用户/后续会话）：今日行与本版行必须结合 n 解读；n<200 只作波动参考；单日 n<30 波动更大。
